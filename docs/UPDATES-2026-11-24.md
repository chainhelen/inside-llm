## Keep the versions separate

Chapters 1–12 explain the early uncached implementation and the pure-ANE learning backend. The later comparison implementation adds independent per-request KV, recurrent state, convolution history, and positions. Its resident backend combines Syrix generation/control with Kapitsa Metal operators, encoding, and loading. New hybrid modes are not claims that the original pure-ANE path secretly falls back to GPU.

Historical M5, M3 Ultra, and M4 Pro measurements describe different revisions and protocols. A toy scheduler's time units and a row-count ratio are not measured latency or throughput. Weight payload sizes exclude scale/bias and do not measure DRAM traffic. A single command buffer still contains multiple dispatches.

## Selected recorded measurements

- Early M5 ANE-prefill/GPU-decode probe: serial and pipelined scheduling produced identical 993280-logit payloads under a fixed continuation. Relative L2 differences against CPU were 2.84701% for prefill and 1.12203% for decode. This was a fixed-ID probe, not proof of identical free generation or of the newer resident backend.
- M3 routed batching: accumulated routed-branch time across 40 layers fell from 558 to 225 ms; the newer shared branch took 356 ms. These overlapping intervals cannot be summed to reconstruct total time. Three-round single-decode medians for the `Hi` prompt were 916 ms for GPU only and 1022 ms for GPU plus ANE.
- Resident Metal, three-round HTTP protocol with 76 input and 8 output tokens: Syrix/Kapitsa recorded 140.36/140.73 tok/s on M3 and 85.35/87.98 on M4. Same outputs in this protocol do not establish universal numerical equivalence.
- Hybrid vocabulary, 17-token Chinese prompt, three-round decode medians: M3 GPU-only 7.37 ms; ANE splits of 8192 and 32768 rows gave 8.07 and 9.00 ms. M4 recorded 11.33, 11.60, and 17.35 ms respectively. A larger ANE allocation was slower in this experiment.
- M5 near tie: GPU scores 16.952305 (ID 17) and 16.952019 (ID 15) both round to 16.953125 in fp16. The smaller-ID tie rule changes the winner. The newer hybrid implementation explicitly rechecks an ANE interval on GPU under a close-score heuristic; this is not a general equivalence guarantee.

## November 24 M4 verification comparison

The updated tutorial compares Apple's `qmv_mma` snapshot `b835fb3` with a ported Kapitsa kernel. Current MLX already has small-row kernels: this lesson does not claim their absence.

| Boundary                                            | Apple kernel | Ported kernel |
| --------------------------------------------------- | -----------: | ------------: |
| Fixed eight-row, 5-bit QKV GPU execution            |     75.20 µs |      71.49 µs |
| Python call, batch of 16 calls (per-call reporting) |     133.0 µs |      146.7 µs |
| Fixed eight-row full verification                   |     76.26 ms |      76.77 ms |
| 4054-token prompt, same 65 output IDs               |  48.57 tok/s |   54.82 tok/s |
| Verification rounds in that generation              |           22 |            17 |

The generation result includes a change in verification-round count. It does not prove that each fixed verification became faster. The older 9.7% result used another baseline (mlx-vlm 0.7.12 / MLX 0.32.4) and is not mixed into this table.

The general BF16 counterexample uses 2048 input values of 131072 and weights of 1: the exact dot product is 268435456. Converting inputs directly to fp16 overflows; the tested port produced NaN. Kapitsa's particular QKV path normalizes first. With this checkpoint's maximum input-normalization scale of 1.796875, its mathematical bound is about 81.32 after normalization. That model-specific precondition cannot be assumed by a general BF16 matrix API, and it does not excuse nonfinite arithmetic before normalization.
